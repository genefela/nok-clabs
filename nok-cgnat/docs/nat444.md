# NAT444 IPv4 Lab

## Scope

Default lab target: **SR7 with ISA2-BB**. This covers the common metrics
required for 95% of the use case. ESA-only VM, CPU, and temperature metrics
are not emulated by SR-SIM and must be documented and validated separately on
actual ESA customer deployments.

The original SR-1e proof and the SR7 target are separate Containerlab labs,
both independent of the DS-Lite topology. SR7 is the default target and uses
SR-SIM 26.7 with an IOM4-E and ISA2-BB MDA 1/2. Neither topology replaces or
reconfigures the other running labs.

Traffic path:

```text
customer namespace     CPE WAN           provider group 2       outside server
192.168.1.50/24  ->  100.64.1.10/24  ->  198.51.100.128-.254  ->  192.0.2.2/30
192.168.1.50/24  ->  100.64.1.11/24  ->  same public pool      ->  same server
```

The first NAT is CPE Linux masquerade. The second is SR OS NAT44 between
inside VPRN 700 and outside VPRN 500. There is no inside IPv4 default route
that bypasses NAT. Outside filter 700 drops un-translated `100.64.0.0/10`.
There is no BGP export in this isolated variant.

## Build and Deploy

Run from the `nok-cgnat` directory of the feature checkout. Docker network
permissions and a valid, ignored `srsim-lic-26.7.txt` are required. The CPE
image installs `iptables` and `ip6tables`; base network-multitool lacks them.

```bash
make nat444-sr7-deploy CLAB=/root/eac/netopskube/tools/clab
```

The older SR-1e proof is still available as a separate lab:

```bash
make nat444-deploy CLAB=/root/eac/netopskube/tools/clab
```

The default `CLAB` command is `containerlab`; override it if the binary is
elsewhere. The image is built by `nat444-build`, a deployment prerequisite.
The SR-1e proof topology is `topo-nat444.yaml`, lab name `sros-nat444`,
management network `nat444` (`172.21.40.0/24`). The SR7 topology is
`topo-nat444-sr7.yaml`, lab name `sros-nat444-sr7`, management network
`nat444-sr7` (`172.21.41.0/24`). SR7 CPM A management is `172.21.41.11`.

CPE startup configures namespaces but intentionally leaves test traffic off.
After the router finishes booting, verify `show isa nat-group 2` reports
`inService` and `show service service-using` reports VPRNs 500/700 Up.
Early customer pings can fail while the IOM/ARP state is becoming ready.

## Tests and Traffic

PyYAML is required; CI uses PyYAML 6.0.2.

```bash
# Offline: no router, license, Kubernetes or traffic mutation required.
make test

# Live: stops only this NAT444 lab's client generators before finite tests.
make nat444-test

# SR7 live test and sustained traffic controls
make nat444-sr7-test
make nat444-sr7-traffic-start
make nat444-sr7-traffic-stop

# Sustained low-rate ping, TCP and UDP after acceptance checks.
make nat444-traffic-start
make nat444-traffic-stop
```

`nat444-test` runs artifact checks and three opt-in runtime tests against the
SR-1e proof by default. `nat444-sr7-test` selects the SR7 containers for the
same traffic checks. The
runtime tests cover both customers, TCP and UDP in forward/reverse directions,
and simultaneous packet captures on the CPE WAN and public side. UDP acceptance
currently requires zero lost packets in each short sample, not a long-term SLA.

Reverse-only UDP initially stopped after about 15 seconds. The provider NAT
policy now explicitly enables `udp inbound-refresh true`, and a 25-second
reverse test on each CPE checks that receive traffic survives the initial UDP
mapping timeout. This is a deliberate test-policy choice, not a blanket
production recommendation: inbound packets can keep an existing mapping alive.

Sustained tests use separate forward/reverse sessions, not `--bidir`. CPE1 uses
TCP 5203/6203 and UDP 5303/6303; CPE2 uses 5204/6204 and 5304/6304. The generators
target 7.2 kbps and 100-byte payloads; TCP ACKs and segmentation mean this is
not an exact wire-packet-rate guarantee. iperf sessions last 24 hours; pings
continue until `nat444-traffic-stop` or container teardown.

Logs inside each CPE: `/tmp/nat44-ping.log`, `/tmp/nat44-tcp.log`,
`/tmp/nat44-tcp-reverse.log`, `/tmp/nat44-udp.log`, `/tmp/nat44-udp-reverse.log`.
Do not run finite tests concurrently with sustained sessions on the same ports.

## Metrics and Grafana

Requires the existing `nok-cgnat` observability package, device credentials,
controller, gNMIc operator/cluster, Prometheus, and Grafana operator. It does
not install the base platform. Verify the pipeline includes availability,
saturation and datapath subscriptions; their definitions alone are insufficient.

```bash
make nat444-observe KUBECTL=/usr/local/bin/kubectl KUBE_CONTEXT=kind-nok-demo

# Adds a separate SR7 device target and SR7-specific dashboard.
make nat444-sr7-observe KUBECTL=/usr/local/bin/kubectl KUBE_CONTEXT=kind-nok-demo
```

This applies only the new opt-in NDT, a dashboard ConfigMap, and a
GrafanaDashboard. It never uses the default Kubernetes context implicitly.
SDCIO is disabled for this target; its C-26.7.R1 model discriminator is not
an assertion that a full SDCIO lifecycle has been validated.

SR7 dashboard: `CG-NAT NAT444 - SR7 ISA`, UID `cgnat-nat444-sr7`. Its queries
select source `nok-cgnat/clab-sros-nat444-sr7-nat-a`, NAT group 2, and MDA
measurements only. It does not imply ESA metrics are present.

```text
http://portal.nok.local:8080/nok-cgnat/grafana/d/cgnat-nat444-sr7?from=now-15m&to=now&refresh=10s
```

All queries select source `nok-cgnat/clab-sros-nat444-nat` and NAT group 2.
The seven panels show service state, degraded flag, flow resources, matched
packet rate, new-flow rate, flow use/max, and flow-creation failures.
There is no misleading DS-Lite forwarding panel on this NAT444 dashboard.
Allow at least two 60-second samples for rate queries. Few new flows during
steady traffic is normal. Dashboard provisioning does not validate log delivery.

## SR-1e Proof Verified on 2026-11-03

- Provider config committed on SR-SIM; group 2 inService and non-degraded.
- VPRNs 500 and 700 Up; public pool active; filter 700 attached and saved.
- Both overlapping customers passed pings, 3/3 replies each, 0% loss.
- Eight finite TCP/UDP forward/reverse tests transferred data; UDP samples had 0% loss.
- Capture test proved CPE WAN source `100.64.1.10` and provider public source
  within `198.51.100.128-.254` for the same customer traffic.
- Thirteen unittest cases passed through `make nat444-test`, including the
  extended reverse-UDP timeout checks.
- Grafana datasource returned group-2 state 2, degraded 0, positive flow
  resources, and increasing NAT packet counters; a sample rate was 57.40 packets/s.
- Grafana operator reported DashboardSynchronized=True for `cgnat-nat444`.

These are functional samples, not capacity or failover benchmarks.

## SR7 Acceptance

SR7 acceptance is pending deployment. Verify group 2 reaches `inService` and
non-degraded, then run `make nat444-sr7-test` and confirm the SR7 Grafana target
reports MDA counters while both customers pass IPv4 TCP/UDP forward and reverse
traffic. Do not treat the SR-1e proof results below as SR7 acceptance.

## Still Open

- ESA-specific customer deployment documentation and validation of VM, CPU,
  and temperature metrics on actual ESA hardware. These metrics are outside
  SR-SIM coverage; do not infer them from MDA measurements.
- Native IPv6 routing and return reachability. CPE IPv6 settings exist, but
  the isolated provider config is IPv4-only; do not claim dual-stack acceptance.
- Two-router SICR, AFTR-2 preference for group 2, MCS, failover and return-route convergence.
- Access aggregation routing and the full SR-MPLS/BGP VPN topology in the design.
- NAT444 binding/flow log export, event correlation, and alert firing/recovery acceptance.
- Negative runtime fault-injection test of RFC6598 leak filtering; the guard is
  configured/applied and valid translated traffic was checked with it enabled.
- Pin/build distribution of the local CPE image for reproducible external environments.
- Review, commit and PR integration of this increment. No changes were pushed automatically.

license/runtime directories to Git. The DS-Lite lab is not a cleanup target.
